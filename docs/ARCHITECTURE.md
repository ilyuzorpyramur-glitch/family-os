## Решения по стеку

| Слой | Выбор | Почему |
|---|---|---|
| Backend | TypeScript, Fastify, Prisma, PostgreSQL | быстрый старт, строгие схемы, один язык с веб и ботом |
| Очереди | Redis + BullMQ | импорт банков, синхронизация, напоминания |
| Web | Next.js (App Router), Tailwind, shadcn/ui | SSR-дашборды, быстрый UI |
| Android | Kotlin, Compose, Room, WorkManager, Hilt | нативный доступ к DevicePolicyManager, UsageStats, VPNService |
| Sync | delta-синхронизация по `updated_at` + outbox | оффлайн-первый, устойчивость к конфликтам |
| Агент | MCP-сервер + скиллы OpenClaw | агент не имеет прямого доступа к БД, только к инструментам |
| Telegram | grammY, webhook | дешёвый канал для всех членов семьи |

Отказ от Kotlin Multiplatform на старте: 90% ценности в Android-интеграциях, web делается
на TS быстрее. Пересмотрим, если понадобится iOS (см. `docs/DECISIONS/0001-stack.md`).

## Домен и границы сервисов

Модульный монолит. Пакеты внутри `apps/api/src/modules`:

- `identity` — семьи, пользователи, роли, приглашения, устройства.
- `guard` — политики, расписания, лимиты, события устройства, геозоны.
- `money` — счета, транзакции, двойная запись, бюджеты, импорт.
- `pantry` — товары, партии, остатки, покупки, списания.
- `nutrition` — приёмы пищи, продукты, рецепты, нормы.
- `quest` — задания, привычки, XP, достижения, награды.
- `copilot` — MCP-шлюз, автоматизации, журнал действий агента.
- `notify` — шаблоны, каналы, тихие часы, дайджесты.

Между модулями — только вызовы через сервисный слой и доменные события
(`transaction.created`, `stock.consumed`, `quest.completed`). Никаких прямых запросов
в чужие таблицы.

## Потоки данных

### 1. Импорт банковской операции
1. Планировщик (BullMQ, cron) запускает `bank-sync` для подключения.
2. Адаптер (GoCardless / Monobank / CSV) отдаёт операции за период.
3. Дедупликация по `(connection_id, external_id)`; fuzzy-матч по сумме/дате/контрагенту.
4. Запись в ledger: две проводки (счёт ↔ категория), правило категоризации.
5. Событие `transaction.created` → бюджет, прогноз, рекомендации агента.

### 2. Сканирование штрихкода
1. Камера → ML Kit Barcode → EAN.
2. Локальный кэш → API `/foods/:barcode` → Open Food Facts.
3. Пользователь правит порцию → запись `meal_item`.
4. Если товара нет — создаём «локальный продукт» и предлагаем подтвердить.

### 3. Родительский контроль
1. Ребёнок разблокирует приложение сверх лимита → локальный `GuardService`.
2. Проверка политики в Room (работает оффлайн), при возможности — подтверждение с сервера.
3. Блокировка экрана/приложения, предложение «попросить время».
4. Событие уходит в API; родитель получает пуш; агент может ответить автоматически.

### 4. Агент OpenClaw
```
Telegram/Web → OpenClaw → MCP tool → API (scoped token) → домен → ответ
```
Агент получает только инструменты, а не БД. Каждый вызов пишется в `agent_audit`
с параметрами и результатом. Записывающие операции (деньги, правила) требуют
`confirm_token` от человека.

## Безопасность и мультитенантность

- Каждая сущность имеет `family_id`; Prisma middleware гарантирует фильтр, тесты — проверяют.
- Роли: `owner`, `adult`, `child`, `agent`. RBAC на уровне маршрутов и сервисов.
- Токены: короткоживущий access (15 мин) + refresh (30 дней), привязка к устройству.
- Детские устройства: отдельный тип токена с ограниченным набором эндпоинтов.
- Шифрование: TLS, pgcrypto для банковских токенов, секреты — вне БД (Vault/ENV).
- Аудит: все изменения правил и денег — неизменяемый лог.

## Наблюдаемость

- Структурированные логи (pino) с `request_id`, `family_id` (хэш), `actor`.
- Метрики: задержка sync, ошибки адаптеров, доля ручных операций, NPS-опросы.
- Трейсинг: OpenTelemetry → OTLP.

## Развёртывание

- `infra/docker-compose.yml` — локальная разработка (Postgres, Redis, MinIO, API).
- Прод: один VPS или Fly.io/Railway; статика web — CDN; APK — GitHub Releases.
- Бэкапы: ежедневный `pg_dump` с шифрованием, хранение 30 дней, проверка восстановления раз в месяц.
