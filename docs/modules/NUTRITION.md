# Модуль Nutrition — калории и БЖУ

## Задачи

1. Записать приём пищи за ≤ 20 секунд.
2. Показать остаток калорий и БЖУ на день.
3. Не превращать еду в бухгалтерию: никаких «штрафов» и морализаторства.

## Поток сканирования

```
Камера → ML Kit Barcode (EAN-13/8, UPC) → локальный кэш → API → Open Food Facts
      → карточка продукта → выбор порции (г/шт) → MealItem
```

- Если продукт не найден: поиск по названию (USDA/локальная база) или ручное создание.
- Штрихкод может быть не пищевым — показываем «это не продукт» и предлагаем поиск.
- Кэш на устройстве — 500 последних продуктов, оффлайн-доступ.

## Нормы

- BMR по Mifflin–St Jeor, TDEE с коэффициентом активности.
- Цель: поддержание / дефицит / профицит — выбирает пользователь, не приложение.
- БЖУ: белок 1.6–2.2 г/кг, жир 25–35%, углеводы — остаток. Значения редактируемые.
- Дисклеймер: не медицинская рекомендация.

## Дневник

- Приёмы: завтрак, обед, ужин, перекус. Время и фото — опционально.
- Быстрое повторение вчерашнего блюда.
- Рецепты: порция = 1/n рецепта, пересчёт ингредиентов.
- Вода — отдельный счётчик (стаканы).

## Отчёты

- День: кольцо калорий + три полосы БЖУ.
- Неделя: среднее, стабильность, дни без записей.
- Семья: кто сколько записал (без сравнения веса и «кто лучше»).

## Связки

- Pantry: рецепт списывает продукты; нехватка → список покупок.
- Money: покупка продуктов попадает в категорию «Еда» и в стоимость рациона.
- Quest: «приготовил ужин», «5 дней с белком в норме» — задания, а не наказания.

## Чего избегаем

- Публичных рейтингов по весу и калориям.
- Автоматических ограничений еды ребёнку.
- Токсичного языка («сожжённые калории», «читмил», «плохая еда»).
