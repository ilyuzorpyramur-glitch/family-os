# Модуль Pantry — дом и запасы

## Идея

Не «склад», а ответ на три вопроса: **что есть**, **что портится**, **что купить**.

## Сущности

- `Product` — товар (название, штрихкод, единица, КБЖУ на 100 г).
- `Location` — место (кухня, морозилка, кладовая, гараж), иерархия.
- `StockBatch` — партия: количество, срок годности, цена, дата покупки.
- `StockMovement` — движение: покупка, расход, порча, корректировка, готовка.
- `ShoppingList` / `ShoppingItem`.

## Сценарии

### Покупка
1. Сканирование штрихкода на кассе или фото чека (M6).
2. Товар найден → добавить партию с количеством и сроком.
3. Если товар новый → создать, заполнить КБЖУ из Open Food Facts.

### Готовка
1. Выбрать рецепт → «приготовить».
2. Система списывает ингредиенты по FIFO (раньше истекает — раньше списывается).
3. Если не хватает — предложение добавить в список покупок.
4. Блюдо добавляется в дневник питания по порциям.

### Просрочка
- Ежедневный job: партии с `expiresAt <= today+3` → уведомление.
- «Спасаем»: рецепты из продуктов, которые скоро истекут.

### Список покупок
- Ручное добавление + автодобавление при остатке ниже порога (`minAmount` у товара).
- Группировка по категориям и месту хранения; отмечание — свайпом.
- Синхронизация между членами семьи в реальном времени.

## Правила

1. Остаток не может быть отрицательным; списание больше остатка — ошибка с предложением скорректировать.
2. Единицы: храним в базовой (`g`, `ml`, `pcs`), ввод — в удобной (кг, л, упаковка).
3. Партии не объединяем: сроки годности важнее простоты.
4. Цена партии — для отчёта «сколько стоит наша еда».

## Метрики

- Доля продуктов с известным сроком годности (> 70%).
- Стоимость выброшенной еды в месяц (цель — снижать).
- Время на пополнение списка покупок (< 2 минут).
