# Family OS

Семейный центр в одном приложении: родительский контроль, деньги, домашние запасы,
питание и геймификация — с агентом OpenClaw, который всё это связывает,
автоматизирует и объясняет.

> **Статус: M2.** Деньги (Zen Money), Guard, Quest, Pantry и питание работают.
> Два приложения: детское (`app.familyos.guard`, зелёное) и родительское
> (`app.familyos.parent`, бирюзовое). Фильтрация сайтов на устройстве — за отдельным
> приложением родителя; сервер хранит правила и статистику.

## Что уже работает

- **Zen Money** — синхронизация счетов по валютам, категорий, доходов/расходов и переводов
  через официальный API (`api.zenmoney.ru/v8/diff/`) по токену с [zerro.app/token](https://zerro.app/token).
- **Двойная запись** — каждая операция раскладывается на проводки, сумма которых равна нулю.
- **Веб-панель** — балансы, итоги месяца, счета и последние операции. Тёмная тема, мобильная вёрстка.
- **Два Android-приложения** собираются в GitHub Actions из одного кода и разделены по роли:
  детское и родительское. Входы не пересекаются: в детском нет родительской панели,
  в родительском нет детского режима.
- **Вход по QR** — родитель показывает QR в приложении, ребёнок сканирует его камерой.
  Код одноразовый, живёт 15 минут; токены в QR не передаются.
- **Guard** — лимит экрана, режим сна, блокировка приложений через Accessibility,
  «+15 минут» за монеты, статистика использования. Device Owner защищает от удаления.
- **Задания по времени** — родитель задаёт окно «с–до», телефон ребёнка блокируется
  на это время сам, кнопки «я закончил» нет.
- **Pantry** — склад с остатками, сканирование штрихкодов камерой, режим покупок
  (список от OpenClaw) и режим использования (списание с указанием количества).
- **Питание** — калории за день, норма на ребёнка, приёмы пищи, неделя.
- **Все доступы** — отдельный экран в детском приложении: обычные разрешения,
  специальные доступы и включение отладки по Wi-Fi с адресом устройства.
- **Quest (геймификация)** — задания от родителя или OpenClaw, XP, уровни, характеристики,
  монеты, магазин наград. Режим подтверждения: родитель или OpenClaw (для фото-заданий —
  ребёнок прикладывает 3 фото). Покупка создаёт запрос родителю, монеты списываются после одобрения.
- **Магазин от детей** — ребёнок предлагает товар с фото, OpenClaw оценивает его в монетах
  и публикует в магазине.
- **MCP для OpenClaw** — деньги, Guard и Quest: `accounts_list`, `money_summary`,
  `guard_set_limit`, `quest_create`, `quest_approve`, `shop_add`, `purchase_decide` и др.
  Все вызовы аудируются.
- **Self-hosted** — один контейнер, SQLite в томе, без внешних зависимостей кроме Zen Money.

## Быстрый старт (Docker)

```bash
cp .env.example .env
# впишите ADMIN_TOKEN и FAMILYOS_SECRET:
#   openssl rand -base64 24   → ADMIN_TOKEN
#   openssl rand -hex 32      → FAMILYOS_SECRET
docker compose up -d --build
```

Откройте `http://localhost:3001`, войдите с `ADMIN_TOKEN`, затем
**Настройки → Zen Money** → вставьте токен с [zerro.app/token](https://zerro.app/token) →
**Синхронизировать**.

## Локальная разработка

```bash
npm install
ADMIN_TOKEN=dev-token FAMILYOS_DATA_DIR=./data npm run dev
# http://localhost:3001
```

Тесты: `npm test` (9 тестов: API, MCP, импорт, двойная запись, сводка, Guard, Guard MCP, Quest, Shop).

## Подключение OpenClaw

```json
{
  "mcpServers": {
    "family-os": {
      "url": "https://your-host/mcp",
      "headers": { "Authorization": "Bearer $AGENT_TOKEN" }
    }
  }
}
```

Инструменты возвращают суммы в валюте операции и `asOf`. Записывающие действия
(`add_transaction`) помечаются `source=agent` и попадают в `agent_calls`.

## Безопасность

- Один администратор на инстанс (мультироли — в M1.5). Токены — только в заголовке или HttpOnly-cookie.
- Токен Zen Money шифруется AES-256-GCM ключом `FAMILYOS_SECRET`.
- Секреты не попадают в логи; MCP-вызовы аудируются в `agent_calls`.
- Подробности: [docs/SECURITY-PRIVACY.md](docs/SECURITY-PRIVACY.md).

## Нагрузка

Замер на этой VM (4 vCPU, 15 ГБ RAM, SQLite в WAL):

| Параллельных запросов | Запросов/с | p50 | p95 |
|---|---|---|---|
| 1 | 138 | 6 мс | 11 мс |
| 10 | 180 | 53 мс | 59 мс |
| 50 | 158 | 283 мс | 436 мс |

Приложение обращается к серверу одним `bootstrap`-запросом и держит ответ 5 минут
в локальном кэше. Один активный телефон даёт около 0,005 запроса в секунду.
Запас этой VM — примерно 5–10 тысяч устройств при таком профиле; узкое место
не CPU, а один процесс и блокировки записи SQLite, поэтому дальше — реплики на чтение
и вынос записи.

## Ограничения

- Фильтрация сайтов на уровне DNS описана в коде (`DnsVpnService`), но не проверена
  на живом трафике: в тестовом контейнере нет прав на TUN-интерфейс.
- Сканирование камерой не проверено там же: у контейнера нет камеры (0 устройств).
  В приложении есть ручной ввод как запасной путь.
- Сопряжение ADB как в Shizuku не реализовано: показываем адрес и ведём в нужный
  экран настроек.
